# تخزين ملفات مِعيار في Cloudflare R2

الحسابات والتقييمات والخطط المنظمة وبيانات فهرسة الملفات تبقى في Supabase. محتوى الملفات الجديدة وأصول الخطط المستوردة بعد التفعيل يُحفظ في حاوية R2 خاصة. أصول الخطط الخمس المدمجة في `public/plans/` تبقى في GitHub Pages؛ لا ينقل هذا التحديث الملفات القديمة أو يحذفها تلقائيًا.

## إنشاء حساب وحاوية

1. أنشئ حسابًا من https://dash.cloudflare.com/sign-up وأكّد بريدك.
2. افتح **R2 Object Storage** وفعّل الخدمة. قد يطلب Cloudflare وسيلة دفع لتفعيل R2؛ راجع الحصة المجانية والتسعير الظاهر في حسابك. الاستخدام الزائد يُحاسب وفق شروط Cloudflare، وحدود التطبيق ليست سقف فاتورة.
3. اضغط **Create bucket**، وسمّ الحاوية مثلًا `miyar-files`، واختر التخزين **Standard** والموقع المناسب لك.
4. أبق **Public access** معطّلًا. التنزيل يستخدم روابط S3 موقّعة قصيرة الصلاحية؛ إعداد نطاق عام أو CORS للحاوية غير مطلوب لمسار الرفع الحالي.

## إنشاء مفاتيح S3

من صفحة R2 افتح **Manage R2 API Tokens** ثم أنشئ مفتاحًا بصلاحية **Object Read & Write** للحاوية `miyar-files` فقط. احفظ **Access Key ID** و**Secret Access Key** الظاهرين عند الإنشاء. هذان هما مفتاحا S3؛ حقل Secret Access Key لا يأخذ رمز Cloudflare العام أو API Token بدلًا منه.

خذ **Account ID** من حساب Cloudflare أو من جزء الحساب في عنوان S3:

`https://ACCOUNT_ID.r2.cloudflarestorage.com`

تستخدم طلبات S3 وروابط التنزيل منطقة التوقيع `auto` تلقائيًا، وفق [توثيق R2](https://developers.cloudflare.com/r2/api/s3/api/#bucket-region). لا تحتاج إضافة سر للمنطقة أو تغيير موقع الحاوية.

## حفظ الإعدادات على الخادم

في مشروع Supabase افتح **Edge Functions → Secrets**، وأضف:

| السر | القيمة |
|---|---|
| `R2_ACCOUNT_ID` | معرّف الحساب فقط؛ ٣٢ خانة، دون رابط |
| `R2_BUCKET_NAME` | اسم الحاوية، مثل `miyar-files` |
| `R2_ACCESS_KEY_ID` | Access Key ID الخاص بـS3 |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key الخاص بـS3 |

احفظها في أسرار Supabase فقط. لا تضع القيم في `VITE_` أو كود الموقع أو مستودع GitHub أو المحادثة. سير عمل نشر الخادم يحافظ على هذه الأسرار ولا يعيد كتابتها. إذا لم تظهر الإعدادات بعد حفظها وتحديث الصفحة، أعد تشغيل **Set up Miyar backend** لإعادة نشر الدالة.

## التحقق والاستخدام

1. ادخل بحساب الأدمن وافتح **لوحة الإدارة → ملفات المنصة — Cloudflare R2**.
2. اضغط **فحص اتصال R2**. الفحص ينفّذ طلب `ListObjectsV2` موقّعًا للحاوية بحد أقصى عنصر واحد دون إنشاء ملف أو تعديله، ولا يعرض أسماء الملفات في النتيجة. عند الرفض يعرض رقم HTTP ورمز الخطأ المعروف مع إرشاد للإصلاح، ورسالة المزوّد المختصرة بعد حجب القيم الخاصة؛ لا يعرض الاستجابة الخام أو المفاتيح. الفحص متاح للأدمن فقط.
3. ارفع PDF أو PNG أو JPG حتى **٢٠ ميجابايت**. تتحقق الدالة من محتوى الملف الفعلي، وتخزّن البايتات في R2. Supabase يحتفظ بالاسم والنوع والحجم والبصمة SHA-256 وحالة الرفع ومعرّف صاحبه، دون بايتات الملف.
4. عند فشل الاتصال، أعد الرفع بنفس اختيار الملف؛ يُعاد استخدام المعرّف ومفتاح الكائن نفسيهما. الملف الذي اكتمل رفعه لا يُرفع مرة ثانية عند تكرار الطلب.
5. اضغط **تجهيز التنزيل** ثم افتح رابط التنزيل الظاهر. الرابط صالح **٥ دقائق**، والملف يُقدّم كمرفق. أي شخص يملك الرابط يمكنه استخدامه حتى انتهاء صلاحيته، لذا عامله كرابط خاص مؤقت.
6. تظهر أحدث ١٠٠ نتيجة للإدارة، بما فيها الأصول المؤرشفة للخُطط وحالات الرفع غير المكتملة. الحد الحالي **٢٠ ملفًا جديدًا خلال ٢٤ ساعة لكل أدمن**، ويشمل الملفات المؤرشفة من استيراد الخطط. التطبيق لا ينفّذ حذفًا تلقائيًا للملفات.

## أصول الخطط الدراسية

بعد نجاح القراءة بالذكاء الاصطناعي، تُحفظ نسخة أصلية من ملف الخطة في R2 إذا اكتملت إعداداته. تبقى قراءة الخطط محدودة بـ٦ ميجابايت. تظهر في المعاينة رسالة تؤكد حفظ الأصل؛ رابط الأصل ومفتاح الكائن ليسا ضمن واجهة الخطط العامة.

عند نشر الخطة، يتحقق الخادم أن الأصل جاهز، وأنه يخص الأدمن صاحب العملية، وأن بصمته تطابق بصمة الملف الذي قرأه AI، ثم يربطه بالخطة في عمود خاص داخل معاملة النشر. فشل النشر لا يغيّر النسخ السابقة، ويظل الأصل ظاهرًا للإدارة. أرشفة الأصل لا تنشره للطلاب تلقائيًا، ولا تعني اعتماد الخطة من الجامعة.

عندما لا توجد إعدادات R2 مكتملة، يستمر استيراد الخطط كما كان: تُحفظ البيانات المنظمة فقط، وتوضح المعاينة أن الأصل لم يُؤرشف. إذا اكتملت الإعدادات لكن R2 رفض حفظ الأصل، تظهر رسالة خطأ ولا يُدّعى أن الأرشفة نجحت. لا يحفظ التطبيق محتوى الملفات في Supabase Storage كبديل تلقائي.

## حدود الوصول والاختبار

رفع الملفات وفهرسها وفحص الإعدادات وإصدار روابط تنزيلها متاحة للأدمن المتحقق النشط فقط. يُتحقق من الحساب قبل قراءة جسم طلب الرفع الكبير. الجداول وعمليات الكتابة خاصة بدور الخدمة، وبقية واجهة API تحتفظ بحد الطلب المعتاد ١٦ كيلوبايت.

الكود يختبر التوقيع بمتجهات HMAC محسوبة مستقلًا، واختبارات قاعدة PostgreSQL المحلية، ومحاكاة طلبات R2 وأخطاء الصلاحيات وإعادة المحاولة. اختبار اتصال الحاوية الحقيقية يحتاج إنشاء حساب Cloudflare وإضافة الأسرار الأربعة ثم تشغيل الفحص من حساب الإدارة.
