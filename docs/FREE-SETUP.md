# تفعيل مِعيار مجانًا — زوار وحسابات Google

مِعيار موقع ويب مستقل: الواجهة على GitHub Pages، وقاعدة البيانات وتسجيل الدخول في Supabase. لا يحتاج بوتًا أو شراء دومين. اختر خطط Free، مع مراعاة حصص الاستخدام واحتمال إيقاف مشروع Supabase غير النشط مؤقتًا.

التقييم متاح للزائر دون Google أو تفعيل Anonymous Sign-ins في Supabase. إعداد Google التالي مخصص للحسابات الاختيارية ولوحة الإدارة.

## مشروعك جاهز للربط

### الدومين المخصص `miyar.website`

- ملفات الموقع تستخدم مسارات نسبية لتعمل على جذر الدومين وعلى مسار GitHub Pages القديم.
- بعد نجاح DNS، انتظر إصدار شهادة GitHub Pages ثم فعّل **Enforce HTTPS**. لا تستخدم تسجيل الدخول عبر HTTP.
- في Supabase: **Authentication → URL Configuration**، اجعل **Site URL** هو `https://miyar.website/`، وأضف `https://miyar.website/` و`https://www.miyar.website/` إلى **Redirect URLs** مع الاحتفاظ بالرابط القديم أثناء الانتقال.
- في Google Cloud، أضف `https://miyar.website` و`https://www.miyar.website` إلى **Authorized JavaScript origins**. اترك رابط إعادة التوجيه الخاص بـSupabase كما هو.
- شغّل **Set up Miyar backend** مجددًا من GitHub Actions لتطبيق قائمة CORS المحدثة للدومين. لا تغيّر أسرار الدخول أو قاعدة البيانات.

تم وضع رابط مشروعك ومفتاحه العام في `src/config.js`:

- معرّف المشروع: `bbnsorjxgehvoddluvyo`
- رابط المشروع: `https://bbnsorjxgehvoddluvyo.supabase.co`
- رابط الموقع: `https://barqstudy.github.io/Professor-Rating/`

هذه معلومات عامة مسموح وجودها في الواجهة. الربط البرمجي لا يُفعّل Google ولا ينشر قاعدة البيانات تلقائيًا؛ أكمل الخطوات التالية.

## ١. أنشئ إعداد Google OAuth المجاني

1. افتح [Google Cloud Console](https://console.cloud.google.com/) بحسابك.
2. من قائمة المشاريع اختر **New project**، وسمّه `Miyar`، ثم اختره.
3. افتح **Google Auth Platform**. إذا ظهر **Get started**، ابدأ الإعداد.
4. ضمن **Branding**، اختر اسم التطبيق `مِعيار`، وبريد الدعم وبريد التواصل الخاصين بك.
5. ضمن **Audience** اختر **External** ليتمكن الطلاب من تسجيل الدخول بحسابات Google، وليس حسابات مؤسسة محددة فقط.
6. لا تضف صلاحيات Gmail أو Drive. التطبيق يحتاج الهوية الأساسية والبريد والملف الشخصي فقط (`openid`, `email`, `profile`).
7. افتح **Clients → Create client** واختر النوع **Web application**. قد تظهر في الواجهة الأقدم باسم **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
8. اسم العميل: `Miyar Web`.
9. في **Authorized JavaScript origins** أضف هذا الأصل فقط، دون مسار:

   ```text
   https://barqstudy.github.io
   ```

10. في **Authorized redirect URIs** أضف عنوان Supabase التالي حرفيًا:

    ```text
    https://bbnsorjxgehvoddluvyo.supabase.co/auth/v1/callback
    ```

11. اضغط **Create**. احتفظ بـ **Client ID** و **Client Secret**. لا ترسل Client Secret في المحادثة ولا تضعه في المستودع.
12. إذا كان التطبيق في **Testing**، أضف بريدك في **Test users** لتجربته. قبل دعوة الطلاب، انشر إعداد الموافقة إلى **In production / Publish app** من Audience. لا يعني هذا نشر كود الموقع؛ إنه يفتح الدخول للمستخدمين خارج قائمة الاختبار.

إعداد OAuth الأساسي لا يحتاج تفعيل خدمات Google مدفوعة أو شراء اشتراك Apple.

## ٢. فعّل Google داخل Supabase

1. افتح مشروعك في [Supabase Dashboard](https://supabase.com/dashboard/project/bbnsorjxgehvoddluvyo).
2. انتقل إلى **Authentication → Sign In / Providers → Google**؛ قد تظهر القائمة باسم **Providers** مباشرةً.
3. فعّل **Enable sign in with Google**.
4. ضع **Client ID** و **Client Secret** اللذين أنشأتهما في الخطوة السابقة، ثم **Save**. اترك خيار السماح بحسابات بلا بريد مغلقًا.
5. بما أننا نستخدم Google فقط، عطّل **Email provider** وبقية طرق الدخول غير المطلوبة. لا تضف حقل كلمة مرور إلى الواجهة.
6. افتح **Authentication → URL Configuration**.
7. اضبط **Site URL** على:

   ```text
   https://barqstudy.github.io/Professor-Rating/
   ```

8. أضف العنوان نفسه إلى **Redirect URLs**، ثم احفظ.

**عنوان Google redirect مختلف عن عنوان عودة الموقع:** Google يعود أولًا إلى `/auth/v1/callback` في Supabase، ثم يعيد Supabase الطالب إلى رابط مِعيار. تبديل العنوانين يسبب خطأ `redirect_uri_mismatch`.

## ٣. انشر قاعدة البيانات والخادم من GitHub

إن لم تكن نشرتهما سابقًا:

1. من https://supabase.com/dashboard/account/tokens أنشئ **Access Token** باسم `miyar-deploy`.
2. افتح المستودع → **Settings → Secrets and variables → Actions → Secrets**.
3. أضف الأسرار التالية:

   | الاسم | القيمة |
   |---|---|
   | `SUPABASE_ACCESS_TOKEN` | توكن حساب Supabase للنشر |
   | `SUPABASE_DB_PASSWORD` | كلمة مرور قاعدة بيانات مشروعك |

4. `SUPABASE_PROJECT_REF` مضبوط افتراضيًا على مشروعك. لا تحتاج تغييره. مفتاح الخدمة يوفّره Supabase للدالة تلقائيًا؛ لا تنسخه للواجهة.
5. افتح **Actions → Set up Miyar backend → Run workflow** على فرع `main`.
6. انتظر النجاح. يُطبّق الترحيلات، ويحدّث إعداد الإدارة وأصل الموقع، وينشر دالة API، ويفحص الدليل العام.
7. افتح **Actions → Deploy Miyar to GitHub Pages → Run workflow** إذا احتجت إعادة نشر الواجهة.

لا تحتاج متغيرًا لتوكن بوت أو كلمة مرور طالب. إعداد Google Client Secret يكون داخل Supabase فقط. إذا سبق أن أضفت أسرار البوت، لم يعد الكود يستخدمها ويمكنك حذفها من الإعدادات.

## تشغيل مساعد مِعيار

المساعد يحتاج مفتاح API لخدمة ذكاء اصطناعي؛ اشتراك ChatGPT أو تسجيل Google وحدهما لا يفعّلان API.

1. اختر المزود، وراجع التسعير وحدود حسابك: [OpenAI API](https://platform.openai.com/api-keys) و[التسعير](https://openai.com/api/pricing/)، أو [Google AI Studio](https://aistudio.google.com/api-keys) و[تسعير Gemini](https://ai.google.dev/gemini-api/docs/pricing).
2. في مشروع Supabase افتح **Edge Functions → Secrets → Add secret**.
3. عند اختيار OpenAI: أضف `OPENAI_API_KEY` بقيمة مفتاح API الخاص بك. عند اختيار Gemini: أضف `GEMINI_API_KEY` بقيمة مفتاح AI Studio. هذا مفتاح الخدمة، وليس كلمة مرور Google أو مفتاح Supabase العام.
4. إذا كان عندك مفتاحان، أضف `AI_PROVIDER` بقيمة `openai` أو `gemini` لتحديد المزود المستخدم. `AI_MODEL` اختياري؛ الافتراضي `gpt-4.1-mini` أو `gemini-2.5-flash`. تحقق من توفر النموذج في حسابك عند تغييره.
5. افتح الموقع وحدّثه ثم اضغط **مساعد مِعيار**. أرسل سؤالًا عامًا مثل «كيف أغيّر جامعتي؟». عند غياب المفتاح تظهر حالة «قيد التجهيز»؛ وإذا رفض المزود المفتاح أو الفوترة تظهر رسالة تعذّر الخدمة.

لا ترسل المفتاح في المحادثات ولا تحفظه في GitHub Code أو متغيرات `VITE_`. يُرسل السؤال والبيانات المنشورة ذات الصلة إلى المزود. تحد المنصة المحاولات يوميًا لتقليل الاستهلاك، مع بقاء تسعير المزود وفوترته مستقلين؛ حدود مِعيار ليست سقف فاتورة بالدولار.

## ٤. ادخل وامنح حسابك صلاحية الإدارة

1. افتح الموقع واضغط **دخول Google**، واختر حسابك.
2. من Supabase افتح **Authentication → Users**. اعثر على حسابك وانسخ **User UID**؛ يكون على هيئة UUID، وليس بريدك أو رقم الهاتف.
3. في GitHub → **Settings → Secrets and variables → Actions → Variables** أضف:

   | الاسم | القيمة |
   |---|---|
   | `ADMIN_AUTH_IDS` | User UID الخاص بحسابك |

4. لأكثر من أدمن ضع UUIDs مفصولة بفواصل دون مسافات. لا تمنح صلاحية لأول مستخدم تلقائيًا.
5. أعد تشغيل **Set up Miyar backend** لتحديث إعداد الإدارة، ثم أعد تحميل الموقع. ستظهر أيقونة لوحة الإدارة لحسابك بعد تحقق الخادم.
6. أضف الدكاترة أو راجع طلباتهم، ثم راجع التقييمات وانشرها. قبول الدكتور لا ينشر التعليقات تلقائيًا.

قاعدة البيانات الجديدة تحتوي كلية الهندسة وخمسة تخصصات، بدون دكاترة أو تقييمات وهمية. الترحيل الثاني يحافظ على أي بيانات تاريخية موجودة ولا ينسبها إلى حساب Google جديد.

لتعيين سفير، اطلب منه الدخول إلى مِعيار بحساب Google مرة واحدة، ثم افتح **لوحة الإدارة → سفراء مِعيار**، وأدخل بريد حسابه واختر الجامعة واضغط **تعيين سفير**. يمكن تكليف الحساب بأكثر من جامعة. بعد تحديث صفحة السفير يظهر **مساحة السفير**؛ مقترحاته في الإضافات والتصحيحات تظل بانتظار موافقتك. زر **سحب الصلاحية** يوقف صلاحياته لهذه الجامعة دون حذف طلباته السابقة.

راجع مقترحات السفراء وتصحيحات الطلاب في **تصحيحات البيانات ومقترحات السفراء**. قارن الاسم والقسم الحاليين بالمقترح، ثم اعتمد التغيير أو ارفضه مع السبب. عند تغيّر السجل بعد إرسال الطلب، تمنع القاعدة الموافقة على النسخة القديمة. زر التصحيح للطلاب موجود داخل تفاصيل الدكتور؛ تصل حالات الطلبات وقراراتها إلى **متابعة طلباتي** والإشعارات. لا يتطلب تفعيل هاتين الميزتين أسرارًا أو اشتراكات إضافية.

## ٥. اختبر قبل دعوة الطلاب

- زائر غير مسجل يستطيع التصفح والتقييم بعد التعهّد؛ حفظ الملف ومتابعة الطلبات يتطلبان Google.
- من حساب طالب، أرسل تقييمًا. لا يُعرض قبل موافقة الإدارة.
- من حساب أدمن، اقبل طلب الدكتور ثم انشر التقييم.
- افتح الموقع بحساب آخر: لا يظهر اسم الطالب أو بريده أو درجته مع التعليق.
- جرّب التقييد والحظر؛ يتحقق الخادم منهما حتى لو عدّل المستخدم المتصفح.
- جرّب تعديل الاسم والتخصص والمستوى وإعادة التحميل، ثم تسجيل الخروج. تبقى تفضيلات المظهر وحجم الخط، وينهي Supabase جلسة هذا الجهاز.

## الخصوصية وحدود الخطة المجانية

- يحتفظ Supabase Auth ببيانات حساب Google اللازمة للدخول. لا نطلب قراءة Gmail أو Drive.
- جدول الملف والتقييمات يحتفظ بمعرّف حساب UUID والاسم والتخصص والمستوى والدرجة والتقييم. اسم الطالب وبريده ودرجته لا تُعرض مع التقييمات العامة. لا تُعرض الدرجة في شاشة مراجعة التعليقات أيضًا.
- مالك قاعدة البيانات لديه وصول إداري للبيانات؛ لا ندّعي إخفاءها عنه.
- الجداول محمية بـ RLS، دون قراءة أو كتابة مباشرة من المتصفح. مفتاح Publishable عام ولا يمنح صلاحيات الخدمة.
- الخادم يسأل Supabase Auth للتحقق من الجلسة الفعلية، ويشترط هوية Google مؤكدة وطريقة OAuth. لا يعتمد على بريد أو دور أو JWT مفكوك أرسله المستخدم دون تحقق.
- التعليقات تمر بفلتر أولي ثم مراجعة بشرية. الحد خمسة تقييمات خلال ٢٤ ساعة وتقييم واحد لكل حساب/دكتور/مادة.
- المحفوظات والمظهر وحجم الخط محلية على الجهاز. الملف والتقييمات محفوظة على الخادم.
- راقب استخدام Supabase وجهّز نسخًا احتياطية خاصة؛ لا ترفع نسخ قاعدة البيانات إلى المستودع العام.

## حل المشكلات

- **Google لم يُفعّل بعد**: فعّل Google provider واحفظ Client ID وClient Secret في Supabase.
- **redirect_uri_mismatch**: راجع عنوان Google redirect URI في الخطوة ١؛ يجب أن ينتهي بـ `/auth/v1/callback`.
- **access_denied / التطبيق في الاختبار**: أضف بريد التجربة في Google Audience أو انشر إعداد الموافقة.
- **تعود إلى صفحة خاطئة**: راجع Site URL وRedirect URLs في Supabase؛ كلاهما يجب أن يشمل `/Professor-Rating/` والشرطة المائلة الأخيرة.
- **المنصة قيد التجهيز**: انشر الخادم من Actions. وضع رابط المشروع والمفتاح العام وحده لا ينشئ الجداول أو الدالة.
- **لم يظهر الأدمن**: استخدم User UID من Authentication → Users، ثم أعد تشغيل إعداد الخادم وأعد تحميل الموقع.
- **فشل الدخول أو الاتصال**: تحقق من حالة مشروع Supabase؛ قد يتوقف مشروع Free غير النشط مؤقتًا.

## التطوير المحلي

```sh
npm ci
npm test
npm run dev
```

لتجربة البيانات النموذجية دون اتصال:

```sh
VITE_DEMO_MODE=true npm run dev
```

لتجربة Google محليًا، أضف عنوان العودة المحلي `http://localhost:5173/Professor-Rating/` إلى Supabase Redirect URLs وأضف `http://localhost:5173` إلى سر `ALLOWED_ORIGINS` لمشروع التطوير. يجب أن تبدأ من صفحة الموقع على المسار نفسه. استخدم مشروع اختبار منفصلًا عند الحاجة، وعدّل **كلًا من** رابط المشروع والمفتاح العام في `.env.local`، ولا تغيّر إعدادات الإنتاج عشوائيًا.
