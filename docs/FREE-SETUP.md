# تفعيل مِعيار مجانًا

الكود والواجهة يظلان في GitHub وGitHub Pages. Supabase يوفر قاعدة PostgreSQL ودالة خادم للتحقق من تيليجرام. اختر خطة **Free**؛ لا حاجة لدومين مدفوع. الخطط المجانية لها حصص استخدام، وقد يتوقف مشروع Supabase مؤقتًا بسبب الخمول. راقب صفحة الاستخدام؛ هذه ليست خدمة بلا حدود.

**لم يُنشأ مشروعك ولم تُنشر قاعدة بياناتك تلقائيًا.** تحتاج إنشاء حسابك وإدخال الأسرار بنفسك في الإعدادات الآمنة أدناه. لا ترسل توكنات أو كلمات مرور في المحادثة، ولا تضعها في ملفات المستودع أو متغيرات تبدأ بـ `VITE_`.

## ١. أنشئ مشروع Supabase

1. افتح https://supabase.com/dashboard وسجّل الدخول باستخدام GitHub.
2. أنشئ منظمة بالخطة **Free** ومشروعًا باسم `Miyar`.
3. اختر منطقة مناسبة، واحفظ كلمة مرور قاعدة البيانات في مدير كلمات المرور.
4. انتظر اكتمال الإنشاء. من إعدادات المشروع انسخ **Project Reference / Reference ID**: رمز المشروع، مثل `abcdefghijklmnopqrst`.
5. رابط المشروع هو `https://<Project Reference>.supabase.co`، وهو رابط عام وليس سرًا.
6. من https://supabase.com/dashboard/account/tokens أنشئ Access Token باسم `miyar-deploy`. هذا سر خاص بالنشر، وليس `anon key` ولا `service_role key`.

لا تحتاج نسخ مفتاح service role: Supabase يوفّره تلقائيًا لدالة الخادم. لا تستخدمه أبدًا في الواجهة.

## ٢. أنشئ بوت تيليجرام

1. افتح الحساب الرسمي **@BotFather** في تيليجرام، ثم `/newbot`.
2. اختر الاسم `مِعيار` ويوزرًا متاحًا ينتهي بـ `bot`.
3. احفظ **Bot Token** بشكل آمن.
4. من `/mybots` اختر البوت ثم إعدادات **Menu Button**، واضبط العنوان «افتح مِعيار» والرابط:
   `https://barqstudy.github.io/Professor-Rating/`

توكن البوت يخص هذا البوت تحديدًا، وهو الذي يستخدمه الخادم للتحقق من توقيع بيانات الطلاب. الدخول العادي من المتصفح يتيح التصفح فقط؛ التقييم وتعديل الملف يتطلبان فتح الميني آب من البوت.

## ٣. أدخل إعدادات GitHub

افتح المستودع → **Settings → Secrets and variables → Actions**.

### تبويب Secrets → New repository secret

| الاسم | القيمة |
|---|---|
| `SUPABASE_ACCESS_TOKEN` | توكن حساب Supabase من الخطوة ١ |
| `SUPABASE_DB_PASSWORD` | كلمة مرور قاعدة بيانات المشروع |
| `TELEGRAM_BOT_TOKEN` | توكن BotFather |

### تبويب Variables → New repository variable

| الاسم | القيمة |
|---|---|
| `SUPABASE_PROJECT_REF` | رمز المشروع فقط، دون رابط أو شرطات مائلة |
| `VITE_SUPABASE_URL` | رابط المشروع الكامل `https://<reference>.supabase.co` |
| `VITE_TELEGRAM_BOT_USERNAME` | يوزر البوت دون `@` |

لا تضع المفاتيح السرية في تبويب Variables. لا تحتاج `anon key` في هذا التصميم؛ الدالة تتحقق بنفسها من توقيع Telegram، وقاعدة البيانات مغلقة أمام الوصول المباشر من المتصفح.

## ٤. شغّل تجهيز الخادم

1. من تبويب **Actions** افتح **Set up Miyar backend**.
2. اضغط **Run workflow** على فرع `main`.
3. انتظر النجاح. التنفيذ يتحقق من البوت دون إرسال رسائل، ويطبّق ترحيل قاعدة البيانات، ويضبط أسرار الدالة، وينشرها، ثم يطلب الدليل العام للتحقق من الاتصال.
4. شغّل **Deploy Miyar to GitHub Pages** من Actions ليبني الواجهة بمتغيرات مشروعك.
5. افتح البوت واضغط «افتح مِعيار». يجب ظهور عبارة «تقييمات مشتركة بين الطلاب» بدل «نسخة عرض تجريبية».

قاعدة البيانات تبدأ بكلية الهندسة وخمسة تخصصات، **بدون دكاترة أو تقييمات وهمية**. سجلات العرض القديمة لا تُرفع تلقائيًا ولا تُخلط مع البيانات الفعلية.

## ٥. فعّل حساب الأدمن

1. افتح إعدادات مِعيار من داخل البوت. سيظهر **معرّفك في تيليجرام** بعد التحقق من الدخول.
2. أضف في GitHub → Actions → Variables متغيرًا باسم `ADMIN_TELEGRAM_IDS` وقيمته رقمك. لأكثر من أدمن استخدم أرقامًا مفصولة بفواصل دون مسافات.
3. أعد تشغيل **Set up Miyar backend**. يحدّث الأسرار دون حذف البيانات أو إعادة إدخال البيانات الأولية.
4. أغلق الميني آب وافتحه مجددًا. ستظهر أيقونة **لوحة الإدارة** لهذا الحساب فقط.

الأدمن يُحدّد من إعدادات الخادم، لا من الاسم أو اليوزر أو localStorage. عدم تعيين `ADMIN_TELEGRAM_IDS` يعني عدم وجود أدمن، ولا يمنح الصلاحية لأول مستخدم عشوائيًا.

## ٦. جرّب مسارًا حقيقيًا قبل دعوة الطلاب

- أضف دكتورًا من الإدارة، أو أرسل أول تقييم له كطالب.
- وافق على طلب الدكتور، ثم راجع التقييم وانشره من قسم مراجعة التقييمات.
- افتح المنصة بحساب آخر: يظهر التعليق والمادة والمؤشرات، ولا تظهر هوية الطالب أو درجته.
- جرّب حسابًا مقيّدًا: يرفض الخادم إضافة تقييم منه. الحظر يمنع الدخول إلى الملف والعمليات المحمية.
- تأكد أن الدرجة والهوية لا تظهران في شاشة مراجعة التعليقات أيضًا؛ يظهر معرّف الطالب للأدمن لأغراض الحظر فقط.
- جهّز نسخة احتياطية خاصة دورية من قاعدة البيانات، لا تحفظها في المستودع العام. يمكنك تصديرها بأدوات PostgreSQL من جهازك. إدارة نسخك الاحتياطية تقع عليك في الخطة المجانية.

## الخصوصية وحدود الاستخدام

- تحتفظ قاعدة البيانات بمعرّف تيليجرام والملف الشخصي والدرجة والتقييم لتنفيذ الصلاحيات ومنع التكرار. لا تُقدّم للطلاب إلا البيانات العامة المنشورة.
- مالك مشروع قاعدة البيانات لديه وصول إداري للبيانات؛ لا نَعِد بإخفائها عن مالك قاعدة البيانات.
- جميع الجداول محمية بـ RLS، دون سياسات قراءة أو كتابة للمتصفح. دالة الخادم تستخدم مفتاح الخدمة داخليًا فقط.
- جميع التعليقات تحتاج مراجعة بشرية قبل النشر، إضافة إلى فلتر كلمات مسيئة وروابط وبيانات تواصل. الفلتر لا يغطي كل صور الإساءة، لذلك المراجعة مطلوبة.
- الحد خمسة تقييمات لكل ٢٤ ساعة وتقييم واحد لكل طالب/دكتور/مادة. جلسة Telegram صالحة لساعة؛ عند انتهائها أغلق الميني آب وافتحه.
- المحفوظات والمظهر وحجم الخط محلية على الجهاز. الاسم والتخصص والمستوى محفوظة على الخادم بعد تفعيل الربط.
- إذا فشل الاتصال، تعرض الواجهة خطأ وتتيح إعادة المحاولة؛ لا ترجع سرًا إلى بيانات نموذجية وتدّعي أنها حقيقية.

## حل المشكلات

- **Missing settings**: أضف أسماء الإعدادات المذكورة في سجل Actions، ثم أعد تشغيل إعداد الخادم.
- **database password / connection**: تحقق من كلمة مرور قاعدة البيانات وحالة المشروع في Supabase؛ يمكن إعادة تعيينها من إعداداته وتحديث السر في GitHub.
- **نسخة عرض تجريبية**: تحقق من `VITE_SUPABASE_URL` ثم أعد تشغيل نشر الواجهة؛ تغيير Variables لا يعيد بناء الموقع تلقائيًا.
- **تعذّر الاتصال بالخدمة**: افتح نتيجة إعداد الخادم وتحقق من نجاح الترحيل والنشر والفحص الأخير؛ أعد تشغيل المشروع إذا توقف بسبب الخمول.
- **افتح من داخل البوت**: فتح الرابط داخل متصفح تيليجرام العادي ليس ميني آب. استخدم زر Menu Button الذي ضبطته في BotFather.
- **لم يظهر الأدمن**: رقم Telegram الصحيح هو المطلوب، وليس يوزر البوت أو رقم الهاتف. أعد تشغيل إعداد الخادم بعد تعديله وأعد فتح الميني آب.

## تشغيل محلي للمطور

```sh
npm ci
npm test
npm run dev
```

انسخ `.env.example` إلى `.env.local` وضع رابط مشروع الاختبار العام إذا رغبت. أضف أصل التطوير مثل `http://localhost:5173` إلى سر `ALLOWED_ORIGINS` في مشروع الاختبار. تسجيل الدخول الحقيقي يتطلب ميني آب يعمل عبر HTTPS؛ لا تزوّر `initData` في الواجهة.

للنشر بالـ CLI بدل GitHub Actions، استخدم Supabase CLI الرسمي لتسجيل الدخول وربط المشروع وتطبيق `supabase db push` ثم `supabase functions deploy miyar`. أدخل الأسرار عبر إعدادات Supabase → Edge Functions → Secrets؛ لا تكتبها في أوامر محفوظة أو ملفات متتبّعة.
