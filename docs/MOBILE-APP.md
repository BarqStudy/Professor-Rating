# تطبيق مِعيار — Android وiOS

المعرّف: `website.miyar.app`، الاسم: **مِعيار**. مشروع Capacitor 8 يضم ملفات الواجهة محليًا؛ الاتصال بالخادم مطلوب للتقييمات والخطط والطلبات والمساعد. الموقع يستمر كالمعتاد. تحديث الواجهة المجمّعة في التطبيق يستلزم بناء إصدار جديد؛ تحديث بيانات المنصة على الخادم لا يحتاج إصدارًا.

## ما هو جاهز

- `android/`: مشروع Android Studio، Android 7/API 24 فأعلى، target API 36.
- `ios/App/App.xcodeproj`: مشروع Xcode، iOS 15 فأعلى، iPhone وiPad.
- أيقونات مِعيار، ربط رجوع Google وApple عبر PKCE، زر الرجوع بأندرويد، مشاركة الروابط والبطاقات من قائمة مشاركة الجهاز، فتح الروابط الخارجية في المتصفح، مساحات الشاشة الآمنة والمظهر.
- إيقاف service worker وتثبيت PWA داخل النسخة الأصلية، وعدم إعادة تحميل الواجهة عند استئناف الجلسة.
- حذف الحساب من الإعدادات مع تأكيد كتابي وحذف بيانات التشغيل المرتبطة به. رابط الحذف الخارجي: https://miyar.website/delete-account.html .
- GitHub Actions **Build Miyar mobile apps** يبني APK للتجربة وAAB غير موقّع، ويترجم نسخة iPhone Simulator غير موقّعة على macOS. هذه الملفات ليست نشرًا في أي متجر.

## التجربة والبناء

يلزم Node 22+ (24 مستخدم في CI)، Java JDK 21، Android SDK 36؛ ولـiOS يلزم macOS مع Xcode يدعم Capacitor 8.

```sh
npm ci
npm run mobile:sync
npm run mobile:android
# أو على Mac:
npm run mobile:ios
```

```sh
npm run android:debug
# android/app/build/outputs/apk/debug/app-debug.apk
npm run android:bundle
# android/app/build/outputs/bundle/release/app-release.aab — غير موقّع
```

يمكن تنزيل الملفات من تبويب Actions ← Build Miyar mobile apps ← تشغيل ناجح ← Artifacts. يتطلب GitHub تسجيل الدخول لتنزيلها. APK موقّع بمفتاح تطوير للاختبار فقط. iOS Simulator لا يثبت على iPhone فعلي ولا يرفع إلى App Store؛ بعد حساب Apple يلزم Archive موقّع للجهاز.

## الدخول — قبل تجربة حسابات حقيقية

نشر الخادم يضيف `website.miyar.app://auth/callback` إلى Supabase Auth Redirect URLs **مع الاحتفاظ بالروابط الحالية**. يبقى callback مزود Google/Apple إلى Supabase هو عنوان `/auth/v1/callback` الذي تعرضه لوحة Supabase؛ لا تستبدله بعنوان التطبيق في إعداد مزوّد الويب. CORS يسمح فقط بنطاقات الموقع و`https://localhost` و`capacitor://localhost` للنسخة الأصلية.

Google يفتح في متصفح النظام وليس داخل WebView. عند العودة يتبادل التطبيق code مرة واحدة بواسطة PKCE؛ لا يتقبل access tokens في رابط الرجوع. عند إلغاء الدخول يمكن إعادة المحاولة من الزر نفسه.

**Apple لم يُفعّل تلقائيًا**: بعد التسجيل في Apple Developer، جهّز App ID وService ID وReturn URL وKey وفق تعليمات Supabase، ثم فعّل Apple Provider في Supabase Auth. المفاتيح تبقى في لوحة الخادم ولا تضاف للمستودع أو الدردشة. قبل تقديم iOS يلزم استكمال إبطال تفويض Apple عند حذف الحساب باستخدام مفاتيح Apple وتدفق يحتفظ برمز التفويض المطلوب في الخادم بصورة آمنة؛ الحذف الحالي يحذف بيانات مِعيار ولا ينفذ Apple token revocation. لا تقدّم نسخة iOS للمراجعة قبل استكمال واختبار هذه الخطوة ودخول Apple على جهاز فعلي.

## النشر باسم المالك

المالك لا يملك حسابات المتجرين حاليًا. لا يلزم الدفع لبناء APK وتجربته، لكن يلزم للنشر:

1. [Google Play Console](https://play.google.com/console/signup): رسم التسجيل المعتاد 25 USD مرة واحدة، والتحقق من الهوية/الجهاز. الحسابات الشخصية الجديدة قد تتطلب اختبارًا مغلقًا (عادة 12 مختبرًا لمدة 14 يومًا) قبل صلاحية الإنتاج؛ اتبع شروط حسابك الفعلية في Console.
2. [Apple Developer Program](https://developer.apple.com/programs/enroll/): الرسم المعتاد 99 USD سنويًا، والتحقق من الهوية؛ تسجيل منشأة قد يحتاج D‑U‑N‑S. السعر المحلي والضريبة يعرضهما المتجر عند التسجيل.
3. تثبيت معرّف التطبيق قبل أول رفع. أنشئ مفتاح رفع Android **باسمك واحتفظ بنسخة احتياطية آمنة**، ثم Android Studio ← Generate Signed Bundle/APK ← Android App Bundle، وفعّل Play App Signing. لا تستخدم مفتاح debug للإنتاج. ملفات التوقيع مستثناة من Git.
4. في Xcode اختر فريق Apple الخاص بك واضبط Signing & Capabilities، ثم Product ← Archive ← Distribute App ← App Store Connect؛ جرّب TestFlight أولًا. احتفظ بمفاتيح Apple خارج Git.
5. ارفع أرقام Android versionCode وiOS CURRENT_PROJECT_VERSION مع كل إصدار. الإصدار الأول المبدئي 1.0/build 1.
6. أكمل بيانات المتجر، صور شاشة فعلية للهاتف وiPad إذا دعمت iPad، التصنيف العمري، حقوق العلامة، إقرارات المحتوى والخصوصية، وتعليمات المراجع لتجربة الوظائف. اختبر تسجيل الدخول والرجوع والمشاركة والرفع/التنزيل والمراجعة والبلاغات وحذف الحساب على أجهزة فعلية قبل الإرسال. قد يطلب المتجر تعديلات بعد المراجعة؛ القبول غير مضمون.
