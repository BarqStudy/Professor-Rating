# مِعيار | Miyar

منصة سعودية لتقييم دكاترة الجامعة، تتيح التقييم كزائر دون تسجيل الدخول، مع حسابات Google اختيارية للملف والطلبات والإدارة. الواجهة Vite وقاعدة PostgreSQL ودالة خادم لحماية العمليات.

**[خطوات تفعيل Google والخادم مجانًا](docs/FREE-SETUP.md)** — الروابط مضبوطة لمشروع `bbnsorjxgehvoddluvyo`. يحتاج مالك المشروع إعداد Google OAuth داخل Google Cloud وSupabase، ثم نشر قاعدة البيانات والخادم.

## التشغيل

```sh
npm ci
npm test
npm run dev
npm run build
```

لتجربة نسخة العرض المحلية دون اتصال استخدم `VITE_DEMO_MODE=true npm run dev`. في الوضع الفعلي تظهر أخطاء الاتصال بدل الرجوع إلى بيانات نموذجية.

## السلوك

- الزائر يتصفح ويرسل تقييمًا دون Google بعد اختيار الجامعة والموافقة على التعهّد. الحساب والطلبات الشخصية والإدارة تستخدم Google.
- تستعمل المصادقة PKCE مع استعادة الجلسة وتجديدها والخروج عبر Supabase SDK. الخادم يتحقق من التوكن لدى Supabase Auth ومن هوية Google وطريقة OAuth، ولا يثق بدور أو معرّف أرسله المتصفح.
- الدكاترة الجدد والتقييمات بانتظار المراجعة؛ قبول الدكتور لا ينشر التعليقات تلقائيًا.
- المعدلات والإحصاءات مشتقة من التقييمات المنشورة. تشمل الإدارة الكليات والتخصصات والدكاترة والتوثيق والحظر والتقييد، والصلاحيات محددة على الخادم بـ`ADMIN_AUTH_IDS`.
- هوية الطالب وبريده ودرجته لا تظهر في التقييمات العامة. الدرجة لا تظهر في شاشة مراجعة التعليقات. مالك قاعدة البيانات لديه وصول إداري للبيانات.
- ملف الطالب على الخادم، والمحفوظات والمظهر وحجم الخط على الجهاز.
- واجهة عربية RTL مع خط «ثمانية» المرفق ووضعين نهاري وليلي.

## الإعدادات

`src/config.js` يحتوي رابط المشروع ومفتاح Publishable العام اللذين وفرهما المالك. يمكن تجاوزهما بـ`VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY`. لا تضف مفتاح خدمة أو Google Client Secret أو توكن إدارة إلى كود المتصفح أو متغيرات `VITE_`.

Google Client Secret يُحفظ في إعداد Google provider داخل Supabase فقط. نشر الخادم يحتاج `SUPABASE_ACCESS_TOKEN` و`SUPABASE_DB_PASSWORD` في GitHub Secrets. دليل التفعيل يشرح الخطوات والعناوين بالتفصيل.

## قاعدة البيانات والاختبارات

الترحيل الثاني يضيف حسابات Google وقيودها دون حذف البيانات التاريخية أو تغيير ملكيتها. ملفات الترحيل الأولى تبقى كسجل تاريخي؛ التطبيق لم يعد يقبل دخولًا أو إرسالًا عبر البوت.

`npm test` يختبر حدود المصادقة والصلاحيات والخصوصية والمدخلات، ويطبّق الترحيلات على PostgreSQL عبر PGlite للتحقق من حفظ البيانات والقيود وحدود الإرسال. لا يغني هذا عن تجربة OAuth حقيقية بعد تفعيل مزود Google في حساب المالك.

الواجهة تُنشر على GitHub Pages عبر **Deploy Miyar to GitHub Pages**. ترحيل قاعدة البيانات ونشر الدالة عبر **Set up Miyar backend**. الخدمات المجانية لها حصص استخدام وقد يتوقف المشروع غير النشط مؤقتًا.

لفحص الواجهة بمصادقة وشبكة محاكاتين: `npm run test:browser`. يحتاج متصفح Chromium مثبتًا؛ يمكن تحديد مساره بـ`CHROMIUM_PATH`. يشمل الفحص رجوع OAuth عبر PKCE واستعادة الجلسة والخروج ومنع الإرسال كزائر، ولا ينفذ دخولًا حقيقيًا إلى Google.

عرض الدكاترة في منزلق أفقي يدعم السحب وأزرار السابق والتالي، مع اختيار الكلية لإظهار أزرار تخصصاتها. يظهر الرسم الترحيبي على الجوال، وتوجد إعدادات الطالب في زر إعدادات واحد بعد تسجيل الدخول. مؤشرات التقييم تستخدم محورًا من اليسار إلى اليمين: ٠ أحمر و١٠٠ أخضر، مع لون مستقل لكل فئة تقييم.

### الواجهة الزجاجية والإضافة الجماعية

الواجهة تدعم Liquid Glass في الوضعين النهاري والليلي، مع خلفية ضبابية وتعطيل التفاعل خلف البطاقات المفتوحة. للتقييمات رابط `#ratings` ولإضافة التقييم `#review`، مع دعم الرجوع وإعادة التحميل. من لوحة الإدارة اختر تخصصًا والصق حتى ١٠٠ اسم ثلاثي، كل اسم في سطر. تُضاف الدكاترة عبر صلاحيات الأدمن الحالية دون إنشاء تقييمات؛ تُستبعد الأسماء المكررة محليًا، وتبقى بقية الأسماء عند فشل الاتصال لإعادة المحاولة.

### الجامعة الخاصة بكل طالب

تعرض لوحة الإدارة قائمة الجامعات مع زر حذف وتأكيد باسم الجامعة. الحذف للأدمن فقط؛ تُمسح اختيارات الجامعة من الحسابات وجلسات الزوار داخل معاملة الحذف نفسها، مع حفظ الهويات وحالات الحظر والتقييد وكل التقييمات. يُطلب اختيار جامعة أخرى عند تحديث الملف أو الزيارة التالية. الكليات وسجل الطلبات وصلاحيات السفراء تمنع الحذف برسالة تحدد سبب المنع. لا تُحذف سجلات الطلاب أو التقييمات تلقائيًا. عند رفض الحذف يبقى السبب داخل نافذة التأكيد ويمكن إغلاقها دون تعطيل الصفحة.

بعد تسجيل الدخول يختار الطالب جامعة إلزاميًا. يُحفظ الاختيار في حسابه ويمكن تغييره من الإعدادات؛ عند تغييره يُصفّر تخصصه السابق. تُصفّى كليات الطالب ودكاترته والبحث والمحفوظات حسب الجامعة، بينما تبقى لوحة الإدارة قادرة على إدارة الجامعات كلها. الجامعات الأولية: الملك سعود، الملك خالد، ونجران؛ البيانات السابقة تتبع نجران حسب تأكيد المالك. تسمح قاعدة البيانات بتكرار اسم الكلية بين جامعات مختلفة وتتحقق من انتماء التخصص والتقييم للجامعة الصحيحة.

تغييرات `supabase/**` تُشغّل إجراء إعداد الخادم تلقائيًا لتطبيق الترحيلات ونشر الدالة، باستخدام أسرار GitHub الحالية. يبقى التشغيل اليدوي متاحًا. الواجهة تتوافق مؤقتًا مع الخادم السابق إلى أن يكتمل نشره.

### المقارنة ومراجعة التعديلات والبلاغات

- زر «قارن الدكتور» يجمع دكتورين أو ثلاثة من الجامعة المختارة ويقارن مؤشراتهم وعدد التقييمات المنشورة.
- في بطاقة الدكتور يمكن فلترة التعليقات حسب المادة.
- «تقييماتي وطلبات التعديل» في الإعدادات وصفحة التقييمات يعرض مشاركات صاحب الحساب فقط. طلب التعديل لا يغيّر التقييم المنشور؛ موافقة الأدمن تستبدل المادة والتعليق والمؤشرات داخل معاملة واحدة، والرفض يحافظ على الأصل. لا تتغير درجة الطالب الخاصة، ولا تظهر في قائمة المراجعة.
- البلاغات تصل إلى قسم مستقل في لوحة الإدارة؛ رفض البلاغ يبقي المحتوى، وإخفاء التقييم يستبعده من العرض والمؤشرات العامة.
- طلب إضافة الدكتور مستقل عن التقييم، مع التحقق من تخصص الطالب وجامعته وحدود الإرسال.
- تنبيهات المحفوظات تُفحص عند فتح المنصة/العودة إليها ودوريًا كل دقيقة أثناء ظهورها. ترتبط بوقت النشر الفعلي، فلا تُرسل إشعارات بسبب تعديل قديم. أوقات الحفظ وحالة القراءة محليّة لكل حساب؛ المحفوظات السابقة تبدأ بمرجع زمني عند أول استخدام للميزة. الاستعلام يعرض أحدث المنشورات خلال ٩٠ يومًا، بحد ١٠٠ نتيجة لكل دفعة من ١٠٠ دكتور.
- الزخرفة داخل زر التقييم SVG لتفادي عرضها كإيموجي على iPad/iOS.

### ملخص التجارب ومتابعة الطلبات والتثبيت

- ملخص الدكتور يستخرج عبارات متكررة من التعليقات المنشورة فقط، دون نموذج مدفوع أو استنتاجات من تقييمات غير منشورة. لا يظهر قبل ثلاث تجارب، ولا تظهر نقطة إلا إذا وردت في تقييمين على الأقل. العدد المعروض هو عدد التقييمات، وليس عدد الطلاب الفريدين. تستخدم الخدمة أحدث ٥٠٠ تعليق وتوضح حجم العينة عند وجود أكثر منها.
- «متابعة طلباتي» في الإعدادات وصفحة التقييمات تجمع طلبات إضافة الدكاترة وتعديل التقييمات عبر جامعات الحساب، مع سبب الرفض ووقت القرار. القرارات الجديدة تظهر في الإشعارات. القرارات القديمة التي سبقت هذه الميزة ليس لها سبب مسجل.
- رفض طلب إضافة أو تعديل يتطلب سببًا. إخفاء تقييم مُبلّغ عنه يرفض تعديلاته المعلقة داخل المعاملة نفسها ويسجل سببًا لصاحب الطلب.
- فلاتر قائمة الدكاترة في لوحة الإدارة تحفظ البحث والجامعة والكلية والتخصص لكل أدمن على جهازه. يمكن تحديد حتى ١٠٠ نتيجة للتوثيق أو إلغائه أو الإخفاء. الإجراء الجماعي ذري: إن تغيرت حالة أي سجل لا يُطبق جزء من العملية.
- زر «مشاركة بطاقة الدكتور» يُنتج PNG بحجم ١٠٨٠×١٣٥٠ بخط ثمانية، الاسم والمؤشرات والعدد ورابط الصفحة؛ مع تنزيل أو مشاركة الملف عند دعم المتصفح.
- التثبيت متاح من الإعدادات، أو من قائمة المتصفح/المشاركة على iOS. ملف التطبيق وService Worker يدعمان الأيقونات وصفحة واضحة عند انقطاع الشبكة. لا يُخزّن Service Worker صفحات التنقل أو روابط OAuth أو استجابات Supabase؛ يحتاج تحميل التقييمات وإرسالها اتصالًا بالإنترنت.

إحصائيات الصفحة الرئيسية عامة لجميع الجامعات: عدد الكليات كلها، وعدد الدكاترة المعتمدين، والتقييمات المنشورة. مصدر أعداد الدكاترة والتقييمات هو التجميع العام على الخادم؛ لا تتغير باختيار جامعة الطالب ولا تتأثر بحد عرض قائمة الدكاترة.

### مساعد مِعيار

محادثة مؤقتة عن استخدام المنصة والبيانات العامة، مع روابط مصادر ينشئها الخادم. يسترجع الخادم بيانات الدكاترة المنشورة حسب جامعة جلسة الزائر، ويختار حقولًا عامة فقط؛ لا يرسل درجات الطلاب أو هوية أصحاب التقييمات أو سجلات الإدارة أو الطلبات الخاصة. لا يملك النموذج أدوات كتابة أو صلاحيات إدارة، وتُعرض إجابته كنص آمن. روابط المصادر لا تؤخذ من نص النموذج أو من المستخدم.

يدعم الربط OpenAI Responses API أو Gemini GenerateContent API. أضف مفتاح المزود في **Supabase → Edge Functions → Secrets** باسم `OPENAI_API_KEY` أو `GEMINI_API_KEY`. اختَر `AI_PROVIDER=openai` أو `AI_PROVIDER=gemini` عند الحاجة، و`AI_MODEL` اختياري (الافتراضي `gpt-4.1-mini` أو `gemini-2.5-flash`). إذا غاب المفتاح يظهر أن المساعد قيد التجهيز، ولا تُولّد إجابات وهمية أو تُستبدل بنص ثابت على أنه ذكاء اصطناعي. لا تضع مفتاح المزود في Git أو متغيرات `VITE_` أو الواجهة.

إذا أعاد نموذج Gemini خطأ 404، يسترجع الخادم النماذج المدعومة من API ويختار بديلًا نصيًا من Flash، ثم يعيد محاولة التوليد مرة واحدة. الاختيار يُحفظ خمس دقائق لكل بصمة مفتاح ونموذج، وتستخدمه فحوص الإدارة أيضًا. لا يختار Pro أو نماذج الوسائط، ولا يعيد المحاولة على أخطاء الحصة أو المفتاح؛ إتاحة النموذج في القائمة لا تعني حصة توليد مجانية.

الحد الأولي ١٠ محاولات لجلسة المتصفح و٣٠ لبصمة الشبكة عند توفرها و٢٠٠ للمنصة كلها في اليوم بتوقيت UTC. الحجز ذري لمنع تجاوز الحدود بالطلبات المتزامنة، والمحاولة الفاشلة تحتسب احترازيًا؛ هذا حد عدد الطلبات وليس سقفًا ماليًا. المدخلات والسياق والإجابة محدودة الحجم، والاتصال بالمزود مهله ١٨ ثانية. لا تُحفظ المحادثات في قاعدة البيانات أو التخزين المحلي، بل عدادات استخدام فقط. يُرسل السؤال والسياق العام إلى المزود وتطبق سياساته؛ خيار OpenAI `store:false` لا يُعد وعدًا بعدم وجود سجلات تشغيل لدى المزود. يمكن تشغيل المساعد كزائر، وتظل العمليات الإدارية محمية بتحقق Google ودور الأدمن المعتاد.

### سفراء مِعيار وتصحيح بيانات الدليل

من لوحة الإدارة، يعيّن الأدمن سفيرًا ببريد حساب Google سبق له الدخول إلى المنصة، ويحدد جامعة أو أكثر. تظهر للسفير «مساحة السفير» لإرسال إضافات الدكاترة والكليات والتخصصات، أو تصحيح الاسم والقسم داخل جامعات تكليفه فقط. يظل الاختيار الأخير محفوظًا لكل حساب على الجهاز. لا يملك السفير نشر تقييمات أو توثيق دكاترة أو حذف سجلات أو إدارة مستخدمين، ولا تنشر مقترحاته تلقائيًا.

زر «اقتراح تصحيح بيانات الدكتور» داخل تفاصيل الدكتور يتيح للحساب النشط إرسال اسم أو تخصص مصحح في جامعته. هذه الطلبات ومقترحات السفراء تصل إلى قسم «تصحيحات البيانات ومقترحات السفراء» بلوحة الإدارة، مع مقارنة البيانات الحالية بالمقترحة. الموافقة تطبق التغيير وتحفظ هوية الدكتور وتقييماته وتوثيقه؛ الرفض يتطلب سببًا. تظهر الحالة والسبب في «متابعة طلباتي» والإشعارات. التقييم كزائر يظل متاحًا دون Google، بينما تتطلب المقترحات حسابًا لمتابعتها.

يفرض الخادم وقاعدة البيانات نطاق الجامعة وحالة الحساب وصلاحيات السفير، بحد ٢٠ مقترحًا للسفير و٥ تصحيحات للحساب خلال ٢٤ ساعة. سحب الصلاحية يمنع المقترحات الجديدة واعتماد مقترحات السفير المعلقة، مع بقاء السجل وحق الإدارة في رفضها. إذا تغيّر سجل أثناء انتظار التصحيح، تفشل الموافقة بدل الكتابة فوق التغيير الأحدث؛ يعيد الأدمن مراجعة الطلب ويرفض النسخة القديمة مع السبب. جداول الأدوار والمقترحات وسجل القرارات وواجهات إدارتها خاصة بالخادم، ولا تظهر في الدليل العام.

### تقييم الزائر والتعهّد والمتصلون

جلسات الزوار مستقلة عن Supabase Auth: يصدر الخادم توكنًا عشوائيًا بطول ٢٥٦ بت، ولا يخزن إلا بصمته، ويتحقق منه في كل عملية زائر. لا تمنح جلسة الزائر صلاحيات الحسابات أو الإدارة. لكل جلسة خمسة تقييمات خلال ٢٤ ساعة وتقييم واحد لكل مادة ودكتور؛ وتظل المشاركات معلقة حتى المراجعة. توجد حدود إضافية لإنشاء الجلسات والإرسال حسب بصمة الشبكة عند توفر عنوانها؛ البصمة HMAC بمفتاح خاص بالخادم، ولا يُخزن عنوان IP الخام.

التعليق والأوصاف الجاهزة اختياريان، مع ثلاثة مؤشرات رقمية ودرجة الطالب الخاصة. تُحفظ الأوصاف منفصلة عن التعليق وتستخدمها الملخصات عند كفاية البيانات. تُرفض الأوصاف غير المعتمدة والمتناقضة، وتُسجل الموافقة على التعهّد بوقت الخادم. يمكن للأدمن حظر أو تقييد جلسة زائر عبر نوع الحساب ومعرّف الزائر الظاهر في طلب المراجعة. حظر الجلسة ليس تحققًا من هوية شخص عبر الأجهزة أو بعد حذف بيانات المتصفح.

العدّاد هو عدد جلسات المتصفحات النشطة عبر الجامعات خلال ٩٠ ثانية، وليس تقديرًا أو عدد تسجيلات Google. يُرسل نبض كل ٣٠ ثانية أثناء ظهور الصفحة، وتُحذف إشارة التبويب عند إخفائه/إغلاقه قدر الإمكان، ويغطي انتهاء المهلة الانقطاع المفاجئ. تُحسب الجلسة المشتركة بين التبويبات مرة واحدة، وقد تُحسب الأجهزة أو المتصفحات المختلفة جلسات منفصلة. لا يُخزن الحضور أو بيانات API في Service Worker، ولا يظهر رقم ثابت عند تعذر الاتصال.

إشعارات طلبات الجامعات والكليات تُرسل إلى `info@miyar.website` عبر صندوق IONOS بعد إضافة `SMTP_USER` و`SMTP_PASSWORD` في أسرار Supabase. تعرض لوحة الإدارة حالة كل رسالة وتتيح فحص الاتصال وإعادة الإرسال. راجع [إعداد البريد](docs/INSTITUTION-EMAIL.md).

تضم الصفحة الرئيسية أربع بطاقات متساوية ومتتابعة: «الدكاترة وتقييماتهم»، «إضافة دكتور»، «خطتي إلى التخرج»، و«اختيار الدكتور المناسب». يتاح تغيير الجامعة من الزر العلوي مباشرة. نموذج إضافة الدكتور موحّد بين الدليل والخطة: خيار التقييم غير محدد افتراضيًا؛ تركه فارغًا يرسل طلب إضافة فقط، واختياره يطلب التعهّد ثم يرسل التقييم عبر مسار التقييمات الأساسي.
